# AI 글로벌 뉴스 톡 v7.0

더존비즈온 솔루션 기획전략 관점의 글로벌 AI 뉴스 브리핑 + 사내 AI 리터러시 코너를 하나로 묶은
단일 파일 React 앱입니다.

- 프런트: `AiNewsTalk.jsx` (약 121KB, 단일 컴포넌트 파일 · 외부 의존성 없음)
- 서버(선택): `server/` — FastAPI + SQLite 설정 동기화 API
- 필요 환경: React 18 이상 (`useState / useEffect / useCallback / useRef / useMemo`만 사용)
- 폰트/아이콘 외 외부 라이브러리 없음, 빌드 설정 불필요

## 1. 자동 새로고침 시간설정 (신규)

헤더의 `⏰ 시간설정` 버튼으로 스케줄 패널을 엽니다. 두 방식을 **동시에** 켤 수 있습니다.

### 📅 매일 정해진 시각에 자동 갱신
| 항목 | 내용 |
|---|---|
| 실행 요일 | 일~토 개별 토글 + `평일` / `매일` 프리셋 |
| 실행 시각 | `<input type="time">`으로 **최대 8개**까지 추가 (예: 08:30 / 13:00 / 18:00) |
| 프리셋 | `08:30·13:00·18:00`, `아침만` |
| 다음 실행 | 다음 실행 일시 + 남은 시간 실시간 카운트다운 (`2일 13:30:00` 형식) |
| 최근 자동실행 | 마지막으로 자동 갱신된 시각 표시 |

스케줄 계산은 `calcNextRun(times, days, fromMs)`가 담당하며, 현재 시각을 **초과**하는 가장
이른 슬롯을 최대 8일 앞까지 탐색합니다. 비교가 엄격 부등호(`>`)이므로 지정 시각에 정확히
한 번만 실행되고 같은 슬롯이 재실행되지 않습니다. 요일이나 시각이 비어 있으면 `null`을 반환해
예약이 자동으로 비활성화됩니다.

검증된 동작 예시 (평일 3회 설정 기준)

| 현재 | 다음 실행 |
|---|---|
| 화 07:00 | 화 08:30 (당일 첫 슬롯) |
| 화 09:00 | 화 13:00 (당일 다음 슬롯) |
| 화 19:00 | 수 08:30 (익일 이월) |
| 금 19:00 | 월 08:30 (주말 건너뜀) |
| 토 10:00 | 월 08:30 (비지정 요일 건너뜀) |
| 화 08:30 정각 | 화 13:00 (중복 실행 방지) |

### ⏱ 주기 반복 갱신
30초 / 1분 / 5분 / 10분 / 30분 간격 중 선택하여 반복 실행합니다. 남은 초가 헤더와 상태 바에
함께 표시됩니다.

> 갱신 자체는 화면이 열려 있는 동안에만 동작합니다(클라이언트 사이드 스케줄러). 다만 **설정은
> localStorage에 저장되어** 브라우저를 닫았다 열어도 그대로 복원됩니다. 닫혀 있던 동안 지나간
> 예약은 소급 실행되지 않고 다음 슬롯부터 이어집니다.
> 예약과 설정 패널이 모두 꺼져 있을 때는 1초 틱을 돌리지 않아 불필요한 리렌더가 발생하지 않습니다.

## 2. 6개 코너

| 코너 | 내용 |
|---|---|
| 📰 **뉴스톡** | 글로벌 AI 뉴스 + 기사별 `DZ전략분석` 패널 (연관 솔루션 / 전략 중요도 / 대응 우선순위 / 더존 활용 방향 / 원소스·구글뉴스 링크) |
| 🔥 **핫AI코너** | 급상승 AI 키워드 8종, **열기지수 랭킹**, 즉시검토 이슈 요약, 카테고리 분포 차트 |
| 🧪 **경험하기** | 오늘 바로 따라하는 AI 체험 카드 8종 — 단계 가이드 + 복사용 프롬프트 + 체험 진행률 |
| 🎓 **주요지식** | 역할별(기획/영업/개발/경영) 필수 지식 10종 — **30초 요약 / 3분 이해 / 10분 심화** 3단계 깊이 |
| ✅ **체크시사** | 고정 문항 5개 + **불러온 뉴스에서 자동 생성된 문항 2개**, 즉시 채점·해설·등급 판정 |
| 🌿 **나노마음건강** | 60초 박스 호흡(4-4-4-4) 타이머, 기분 체크, 1분 루틴 5종, 마음점수, 오늘의 한 줄 |

### 열기지수 (핫AI코너)
```
열기지수 = 기사 포인트 × 0.6 + 전략 중요도 가중치 × 18 + 대응 우선순위 가중치 × 12
```
중요도(높음 3 / 중간 2 / 낮음 1), 우선순위(즉시검토 4 / 단기검토 3 / 중장기검토 2 / 모니터링 1).

### 체크시사 문항 생성
`seedPick()`이 새로고침 횟수를 시드로 사용해 고정 문항 풀에서 5개를 순환 선택하고, 여기에
현재 로드된 뉴스에서 만든 카테고리 분류 문항 2개가 더해집니다. **새로고침할 때마다 문항 구성이
바뀌므로** 매일 자동 갱신과 함께 쓰면 회차마다 다른 퀴즈가 제공됩니다.

### 마음점수
`기분 체크 60% + 루틴 실천 40%`로 계산됩니다. 호흡 타이머는 경과 초에서 단계·잔여초를
파생시키는 구조라 React StrictMode의 이중 호출에도 단계가 어긋나지 않습니다.

## 3. localStorage 저장

설정과 학습 기록이 브라우저에 자동 저장되어 다음 방문 시 그대로 복원됩니다.
키 접두사는 `dzAiTalk.v1.` 이며, 값이 바뀔 때마다 기록됩니다.

| 키 | 내용 | 초기화 시점 |
|---|---|---|
| `daily` `times` `days` `auto` `interval` | 스케줄 설정 전체 | 수동 초기화 |
| `nav` `cat` | 마지막으로 본 코너 / 뉴스 카테고리 | 수동 초기화 |
| `lastAuto` | 최근 자동실행 시각 | 수동 초기화 |
| `expDone` | 경험하기 체험 완료 진행률 | 수동 초기화 |
| `knowRole` | 주요지식 역할 선택 | 수동 초기화 |
| `mind` | 나노마음건강 오늘의 기분·루틴 (날짜 포함) | **날짜가 바뀌면 자동 초기화** |
| `quizStat` | 체크시사 누적 풀이 횟수 / 최고 정답률 / 연속 일수 | 수동 초기화 |
| `syncUrl` `syncCode` `syncRev` | 서버 동기화 연결 정보 (4장) — 이 값들은 서버로 올라가지 않음 | 연결 해제 / 수동 초기화 |

### 안전 설계
- **접근 전량 방어** — 사생활 보호 모드, 스토리지 차단, 용량 초과, SSR(`window` 부재) 등
  어떤 실패에서도 예외가 밖으로 나가지 않습니다. 저장이 불가능하면 앱은 인메모리 상태로
  정상 동작하며, 패널에 `⚠ 저장 불가` 뱃지와 사유 안내가 표시됩니다.
- **저장값 검증** — 읽어들인 값이 손상·변조된 경우(잘못된 JSON, 타입 불일치, 범위 밖 값,
  시각 9개 이상, 존재하지 않는 역할명 등) 검증 함수를 통과하지 못하면 조용히 기본값으로
  되돌립니다. 손상된 저장값 때문에 화면이 깨지지 않습니다.
- **날짜 스코프** — 나노마음건강의 기분·루틴은 '오늘의 기록'이므로 저장 시 날짜를 함께 기록하고,
  날이 바뀌면 자동으로 비웁니다.
- **중복 기록 방지** — 체크시사 누적 기록은 한 회차당 1회만 반영됩니다(React StrictMode의
  이중 호출 포함).

### 초기화
스케줄 패널 우측 `저장값 초기화` → `초기화` 2단 확인으로 저장된 설정과 기록을 모두 지웁니다.
코너 컴포넌트는 리마운트되어 내부 저장값까지 함께 비워집니다.

## 4. 서버 동기화 (기기 간 공유)

localStorage는 브라우저·기기 단위라 다른 PC와 공유되지 않습니다. 이를 위해
**동기화 코드** 기반의 최소 API 서버(FastAPI + SQLite)를 함께 제공합니다.
서버 설치·API·보안 전제는 [`server/README.md`](server/README.md)를 참고하십시오.

```bash
cd webapp/ai-news-talk/server && uvicorn app:app --port 8000
```

### 사용 흐름
1. `⏰ 시간설정` → `☁️ 서버 동기화`에 서버 주소 입력 (`http://localhost:8000` 또는 `/api` 상대경로)
2. **동기화 코드 발급** → `DZAI-XXXX-XXXX-XXXX` 형식의 코드가 나오고 현재 설정이 서버에 올라감
3. 다른 기기에서 같은 주소를 넣고 그 코드를 입력 → **코드로 연결**
4. 이후 설정이 바뀌면 최대 8초 안에 자동으로 올라가고, 연결 시점에 서버 값을 먼저 받아옴

`연결 해제`는 이 기기에서 코드만 잊고 서버 데이터는 남깁니다.
`서버에서 삭제`는 2단 확인 후 서버 데이터까지 완전히 지웁니다.

### 동기화 대상
localStorage에 저장되는 항목 중 동기화 설정 자체(`syncUrl` `syncCode` `syncRev`)를
제외한 전부입니다 — 스케줄, 마지막 코너·카테고리, 경험하기 진행률, 주요지식 역할,
나노마음건강 오늘 기록, 체크시사 누적 기록.

### 충돌 처리
클라이언트는 자신이 아는 `rev`를 `baseRev`로 보냅니다. 그 사이 다른 기기가 저장해
서버 `rev`가 달라졌으면 서버는 **저장하지 않고** `409`와 함께 현재 상태를 돌려주고,
클라이언트는 서버 값을 받아들인 뒤 *"다른 기기에서 더 최근에 저장한 설정을 받아왔습니다"*를
띄웁니다. 다른 기기의 저장이 조용히 사라지지 않습니다.

### 서버가 없어도
서버 주소를 비워두면 동기화 기능만 꺼지고 앱은 localStorage만으로 완전히 동작합니다.
연결된 상태에서 서버가 죽으면 `⚠ 서버 연결 안 됨`으로 표시되며, 로컬 저장과 화면 동작은
그대로 유지됩니다. 서버가 돌아오면 다음 주기에 자동으로 다시 올라갑니다.

## 7. 사용 방법

`AiNewsTalk.jsx`의 `App`을 기본 export로 가져와 렌더링합니다.

```jsx
import App from "./AiNewsTalk";

export default function Root() {
  return <App />;
}
```

스타일은 컴포넌트 내부 `<style>` 태그로 주입되므로 별도 CSS import가 필요 없습니다.

### 단일 HTML로 빌드 (아티팩트·정적 배포용)

React 없이 열 수 있는 자체 완결형 HTML을 만들려면:

```bash
npm install --no-save react@18 react-dom@18 @babel/core @babel/preset-react
node webapp/ai-news-talk/build-artifact.cjs out.html
```

`build-artifact.cjs`는 원본 JSX를 건드리지 않고 기계적 변환만 합니다 — 모듈 구문 제거,
외부 폰트 `@import` 제거, 폰트 스택 확장, `NET` 플래그 off, JSX 트랜스파일 후
React 18 UMD와 함께 인라인. 산출물은 약 285KB이며 외부 요청이 하나도 없습니다.

#### `NET` 플래그

JSX 상단의 `const NET = true;`는 빌드 시 `false`로 바뀝니다. 이때 뉴스 요청은 데모
폴백으로, `syncFetch`는 오프라인 반환값으로 **요청을 보내기 전에** 갈라집니다.

단순히 실패를 감추려는 게 아닙니다. 아티팩트 게시 환경의 CSP는 외부 호스트를 전부
차단하는데, 그 거부 로그(`Refused to connect ...`)는 **브라우저가 직접 콘솔에 출력하므로
`try/catch`로 막을 수 없습니다.** 요청 자체를 보내지 않아야 콘솔이 깨끗해집니다.

> 게시된 아티팩트에서 **실시간 AI 뉴스는 동작하지 않습니다.** 페이지에서 Claude를 호출할
> 수 있는 런타임 기능이 없기 때문이며, 우회로도 없습니다. 뉴스는 항상 내장 데모 8건
> (`DEMO` 배지)이고 동기화도 비활성입니다. 실시간 뉴스와 기기 간 동기화가 필요하면
> `NET = true`인 원본을 로컬이나 사내 서버에서 실행해야 합니다.
> 시간설정·6개 코너·브라우저 저장은 아티팩트에서도 모두 정상 동작합니다.
